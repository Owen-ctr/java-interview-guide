## 分布式系统中 CAP 理论是什么？

<Badge type="warning" text="难度 ⭐⭐⭐" /> 出现频率：高 ｜ 标签：分布式·CAP

### 一句话答案
CAP 指一致性(C)、可用性(A)、分区容错性(P)，三者不可兼得；分布式系统通常优先保证 P，在 C 与 A 之间权衡。

### 详细解析
- **C 一致性**：所有节点同一时刻数据相同。
- **A 可用性**：每个请求都能得到（非异常的）响应，不保证是最新数据。
- **P 分区容错**：网络分区（节点间失联）时系统仍能对外服务——网络不可靠，所以 P 必选。
- **取舍**：CP 系统（如 ZooKeeper、etcd）牺牲可用性保强一致；AP 系统（如 Eureka、Cassandra）牺牲强一致保可用。

::: tip 延伸
BASE 理论是对 AP 系统的补充：基本可用(BA)、软状态(S)、最终一致(E)，常见于高可用互联网架构。
:::

## 分布式锁有哪些实现方式？

<Badge type="warning" text="难度 ⭐⭐⭐⭐" /> 出现频率：高 ｜ 标签：分布式·锁

### 一句话答案
常见：基于 Redis（SET NX + 过期）、基于 ZooKeeper（临时有序节点）、基于 etcd；核心要保证互斥、防死锁、可重入。

### 详细解析
- **Redis**：`SET key value NX EX` 原子加锁，用 Lua 脚本保证「校验+删除」原子性；需解决锁误删（value 用唯一标识）和锁过期业务未执行完（看门狗续期）。
- **ZooKeeper**：创建临时有序节点，最小序号获锁，释放（会话断开）自动删节点；天然防死锁、可监听唤醒。
- **etcd**：基于租约(lease) + 事务 CAS 实现，类似 Redis 思路。

::: warning 注意
Redis 主从切换瞬间可能脑裂导致锁失效，对正确性要求极高的场景可用 Redlock 或 ZK/etcd。
:::
