# MySQL 事务

## 事务的 ACID 和隔离级别？

<Badge type="tip" text="难度：进阶" />

### 一句话答案
ACID = 原子性/一致性/隔离性/持久性；隔离级别由低到高：读未提交 < 读已提交 < 可重复读(MySQL 默认) < 串行化。

### 详细解析
- **A 原子性**：事务要么全做要么全不做（undo log 保证）。
- **C 一致性**：事务前后数据满足约束。
- **I 隔离性**：并发事务相互隔离（锁 + MVCC）。
- **D 持久性**：提交后落盘不丢（redo log 保证）。
- **隔离级别**：MySQL InnoDB 默认「可重复读」，通过 MVCC + 间隙锁解决大部分幻读。

## 脏读、不可重复读、幻读分别是什么？

<Badge type="tip" text="难度：进阶" />

### 一句话答案
脏读=读到未提交数据；不可重复读=同事务内同条记录两次读结果不同（侧重修改）；幻读=同查询条件两次结果集行数不同（侧重新增/删除）。

### 详细解析
- **脏读**：事务 A 读到事务 B 未提交的修改，B 回滚后 A 拿到脏数据。
- **不可重复读**：A 两次读同一行，期间 B 提交了对该行的修改。
- **幻读**：A 按条件查到 N 行，期间 B 插入/删除符合条件的行，A 再查变成 M 行。
- **解决**：提升隔离级别；InnoDB 在可重复读下用 MVCC + 间隙锁（Next-Key Lock）防幻读。

## MVCC 多版本并发控制原理？

<Badge type="warning" text="难度：深入" />

### 一句话答案
InnoDB 通过隐藏事务 id、回滚指针 + undo log 构建数据多版本，配合 ReadView 实现「快照读」，让读不加锁、读写不阻塞。

### 详细解析
- **隐藏列**：每行有 `trx_id`（最后修改事务）和 `roll_pointer`（指向 undo 旧版本）。
- **ReadView**：记录当前活跃事务集合，判断某版本对当前事务是否可见（已提交才可见）。
- **快照读**：普通 `SELECT` 读快照，不加锁；`SELECT ... FOR UPDATE` 是当前读，读最新并加锁。

## redo log、undo log、binlog 各自作用？

<Badge type="warning" text="难度：深入" />

### 一句话答案
redo log 保证持久性（崩溃恢复已提交数据）、undo log 保证原子性（回滚/实现 MVCC）、binlog 是 Server 层归档日志（主从复制、时间点恢复）。

### 详细解析
- **redo log**：物理日志、循环写、WAL（先写日志再落盘），InnoDB 特有。
- **undo log**：逻辑日志，记录反向操作，用于回滚和 MVCC 旧版本。
- **binlog**：逻辑日志、追加写，主从同步依赖它；两阶段提交保证 redo 与 binlog 一致。
